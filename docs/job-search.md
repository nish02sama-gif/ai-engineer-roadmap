# Job Search Plan

## A realistic picture

Roles titled exactly "AI Engineer" at junior level are competitive, and many ask for experience. You'll do better by applying to a wider band of roles that use the same skills, while your portfolio grows. Target several of these at once:

| Role family | Why it fits |
|---|---|
| Junior AI / LLM application developer | Most direct match for Phases 5-8 |
| Junior ML engineer, data scientist, data analyst | Phases 2-3 plus SQL |
| AI support engineer, technical support engineer at AI or SaaS companies | Your support experience is a real advantage; you can debug, explain, and handle customers |
| Solutions or implementation engineer (junior) | Customer-facing technical work using APIs and RAG |
| AI operations, prompt/evaluation specialist, data annotation lead | A way in while you keep building |

Choosing "support engineer at an AI company" as a stepping stone is a legitimate strategy, not a fallback. It pays, builds credibility, and moves you toward engineering roles.

## When to start

- **Week 4**: resume draft and LinkedIn cleaned up. Start with a handful of applications to adjacent roles.
- **Week 9** (after Phase 4): apply steadily, 5 to 10 applications a week, each tailored.
- **Week 16**: full push with four finished projects.

Don't wait until you feel ready. Interviews teach you what to study.

## Resume

- Lead with a short skills line and **Projects** with links. Employers hiring juniors read projects first.
- Describe your support experience with outcomes: tickets handled, issues diagnosed, escalations resolved, tools used. Use numbers you can verify.
- Each project gets 2-3 bullets in this shape: *built X using Y, which does Z, measured by W*. Example: "Built a RAG question-answering service over product docs using sentence-transformers and the Claude API; answers cite sources and scored 87% on a 60-question evaluation set."
- Only list what you can discuss in an interview. If you can't explain it, cut it.
- One page, plain formatting, saved as PDF.

## Portfolio standard

Every project README includes: problem, demo, how to run it, architecture in a short diagram or list, evaluation results, limitations, and what you'd improve. Include a `tests/` folder and an `.env.example`. A project that a stranger can clone and run in five minutes beats a clever one that doesn't run.

## Interview preparation

Technical topics, in rough order of how often they come up:

1. **Python**: lists/dicts/sets, comprehensions, functions, classes, exceptions, reading files, writing small functions live.
2. **SQL and pandas**: joins, group by, window functions, cleaning messy data.
3. **ML basics**: train/test split, overfitting, precision/recall, cross-validation, choosing a metric.
4. **LLM and RAG**: how a RAG pipeline works, chunking choices, embeddings, why retrieval fails, how you evaluated your system, hallucination handling, cost and latency.
5. **Project deep-dive**: be ready to walk through any project: decisions, mistakes, trade-offs.
6. **Behavioral**: use stories from support work. Difficult customer, ambiguous problem, learning a tool fast, handling pressure.

Practice out loud. Record yourself explaining RAG in 2 minutes.

## Weekly application log

Track every application in a sheet: company, role, date, link, status, follow-up date, notes. Follow up once after 7-10 days. Keep messages short and direct.
